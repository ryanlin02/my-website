## 一、五個階段的成果

### 1. B2 — 抽出 `css/check.css`

| 項目 | 改動前 | 改動後 |
|---|---:|---:|
| `check.html` 行數 | 470 | 222 |
| 內嵌 `<style>` 行數 | 290 | 0 |
| `!important` 實際宣告 | 23 | **0** |

搬移時用程式比對過：**38 條規則一條沒漏、所有屬性值完全一致**。

順帶處理掉兩個結構性問題：

- `.chinese-row` 不再套用 `.row`。舊版為了推翻 `.row` 的背景、陰影、邊框、排列方式用了 6 個 `!important`，現在它是一組單純的獨立樣式。`.row` 剩下沒被覆寫的三個屬性（`border-radius`、`position: relative`、`z-index: 1`）在透明背景、無絕對定位子元素的情況下都不產生視覺效果，所以外觀完全相同。
- 表格首欄寬度選擇器原本寫成 `td:nth-child(1)`，會連年份分隔列那個 `colspan` 的儲存格一起套用 `width: 60px`，在 `border-collapse` 下干擾整張表的欄寬。已改為排除年份分隔列。

### 2. B3 — 備註視窗被手機鍵盤遮擋

支票頁原本自己 new 了一個垂直置中的 `.modal-overlay` 來裝 `<textarea>`，鍵盤一彈出就會把視窗推走或蓋住。現在兩頁共用 `common-keypad.js` 裡的 `showNoteEditor()`，用 `visualViewport.height` 實際算出「扣掉鍵盤後的可視高度」再定位。

**過程中發現計算頁那套其實也是壞的**：`adjustNoteEditorPosition()` 的 `if` 和 `else` 兩個分支設的值完全一樣（都是 `paddingTop: 180px`），等於偵測鍵盤的判斷式從來沒起過作用。兩頁一起修好了。

另外修掉一個潛在破版問題：舊版把備註內容直接寫進 HTML 字串、只跳脫單引號，備註含有雙引號或換行就會把屬性整個切斷。現在改為由對話框自行查出內容並用 `textarea.value` 指定，並新增共用的 `escapeHtml()`。

### 3. 歷史記錄改版與套用資料

舊版用了四個全站 CSS **根本沒有定義**的 class，導致面板幾乎沒有樣式、五個項目擠在兩欄 grid 裡排版錯亂：

| 舊版用的 | 實際存在的 |
|---|---|
| `.no-history` | `.no-data` |
| `.note-btn` | `.detail-btn` |
| `.history-note-display` | `.history-note-preview` |
| `<div><span>總金額：</span>` | `.history-detail-item` + `.detail-label` / `.detail-value` |

已全部改為與計算頁相同的結構，並補上缺少的 `.history-list` 外層容器。

新增的功能：

- **套用資料** —— 業務到客戶端開票的主要入口。一鍵還原總金額、繳款金額、張數、開始日期、清單，**連打勾進度一起還原**。
- **開立進度徽章** —— 列表上直接顯示「已開立完成 20 張」或「開立中 19 / 20 張」。
- 排序改為依儲存時間新到舊（舊版只是把陣列 `reverse`，遇到舊資料順序會亂）。
- `id` 改為 `Date.now() * 1000 + 亂數`。舊版用毫秒時間戳，同一毫秒連按兩次保存會產生相同 id，刪除時會一次刪掉兩筆。
- 所有 localStorage 存取統一走 `readCheckHistory()` / `writeCheckHistory()`，都有 try-catch。無痕模式或容量滿時會跳錯誤提示，而不是靜默壞掉還顯示「已保存」。

### 4. 開票清單改版

這是主菜。清單從「流水號／日期／星期／剩餘張數」四欄，改為六欄：

**打勾欄** —— 整列可點，手指不必瞄準小方框。打勾後該列淡化並劃線。

這是這次改版的核心。你提到「剩餘張數」的用意是讓業務知道開到第幾張，但靜態倒數欄有個前提：得先知道自己在哪一列。一邊聊天一邊開 50 張票，真正會出事的是**看丟行** —— 被打斷後回頭，很容易多寫一張或跳過一張，而這時候倒數欄反而會誤導。打勾把「現在開到哪」變成畫面上的既成事實。

**金額欄** —— 前 n−1 張顯示每期繳款，最後一張顯示尾款金額。

**尾款票整列區隔** —— 紫色底、上緣粗線、標註「尾款票」。整批裡唯一金額不同的那張，必須一眼認出來。

**日期被調整的標記** —— 客戶若是每月 31 號，2 月會變 28、4 月會變 30。程式算得是對的（不會滾雪球，3 月會回到 31），但業務照習慣順手寫 31 就錯了。這幾列現在會加一行小字「原 31 日」。

**日期改精簡格式** `115/04/30` —— 手機只有 400px 寬，`115年4月30日` 排不下金額欄。表格改為 `table-layout: fixed`，50 列也不會因內容長短而跳動。

**開立進度列** —— 清單上方顯示「已開立 7 / 20 張」與「還要開 13 張」。

**已開立合計** —— 這裡跟原本的提案不同，我在動工前先更正過：原先提的「19 張 × 繳款 + 尾款 = 總金額」在數學上永遠成立（尾款本來就是這樣算出來的），不管填什麼都會顯示相符，看起來像檢查其實什麼都檢查不到。改成跟打勾連動：**已打勾的張數 × 該張金額**累加，全部打完才會等於總金額。這樣驗證的是「有沒有漏開、漏打勾」，那才是真的會出錯的地方。測試裡有一項就是取消其中一張，確認合計會少掉對應金額且不再顯示相符。

**打勾寫回歷史記錄** —— 打勾狀態直接存進來源的那筆紀錄，成為實際的開立工作紀錄。

這裡有一個必須處理的細節：**只要改動任何輸入欄位或開始日期，就會切斷與歷史記錄的連結並清空打勾**。否則換票時把總金額換成尾款金額之後，後續打勾會把進度寫回一筆金額已經不同的舊紀錄，把它污染掉。

### 5. 收尾

**以尾款續開下一批** —— 換票那趟過去時，一個按鈕帶完：總金額 ← 這次的尾款金額、開始日期 ← 這次的尾款票日期、繳款金額不變、張數清空待輸入。按下去會先跳確認視窗把要帶入的三個數字列出來，確認後才套用。尾款已經不大於一期繳款時會擋下並說明「這是最後一張票，不需要再續開」。

**螢幕不休眠** —— 清單裡還有未打勾的票時啟用 Wake Lock，全部開完或清空後自動釋放。切換到其他 App 再切回來會重新取得（系統會自動釋放）。不支援的瀏覽器安靜略過。

**欄位釐清** —— 這是我在討論時提出的風險點：

| 位置 | 改動前 | 改動後 |
|---|---|---|
| 張數欄下方 | （無） | `19 張月票 ＋ 1 張尾款票` |
| 鍵盤標題 | 開票張數 | 開票張數（含尾款票） |
| 押票金額 | 押票金額 | **尾款金額** |
| 結束日期 | 結束日期 | **尾款票日期** |
| 唯讀欄位 | 與可點欄位長得一樣 | 加上 `readonly` 樣式 |

「結束日期」這個名字容易被誤讀成貸款到期日，實際上它是尾款票的日期。

新增的 `支票開票流程測試.js` 用一個完整情境跑過整條流程：總額 120 萬、月付 5 萬、客戶給 20 張（19 張月票 + 1 張尾款票），逐項驗證清單內容、打勾、進度、合計、保存、套用、換票。

其中兩項特別值得一提：

**日期不滾雪球** —— 從 115/01/31 開始，驗證 2 月縮到 28 並標記、**3 月要回到 31 且不標記**、4 月縮到 30 並標記。如果日期推算是拿上一張加一個月，3 月就會停在 28，整批日期全錯。

**換票串接不漏錢** —— 第一批開 20 張、以尾款續開第二批 6 張，驗證「第一批月票 + 第二批月票 + 第二批尾款 = 原始總金額 1,200,000」。金額串接錯誤不會有任何報錯，只會讓客戶少付或多付。

另外也做了靜態檢查：所有 JS 通過 `node --check`；頂層名稱重複偵測（同頁載入的多個檔案間若有同名 `let` 會整個腳本停止執行）計算頁 72 個、支票頁 80 個名稱皆無衝突。

`鍵盤行為對照測試.js` 因為你已經 commit 了 B1，原本比對 git HEAD 的做法失效了。改為把改版前的兩份原始碼凍結在 `tests/fixtures/`，之後不依賴 git 歷史也能永遠跑。

## 五、建議下一步

我建議先**實機試用**再繼續改。這次改的是實際作業流程，紙上談兵到這裡差不多了 —— 打勾的手感、字級夠不夠大、50 張票捲動起來順不順、尾款票的顏色在陽光下看不看得清楚，這些只有真的拿手機開一次票才知道。

試用後如果打勾這個機制方向對，下一步值得做的是「捲動時自動停在第一張未打勾的票」，讓業務被打斷後回頭不用自己找位置。
