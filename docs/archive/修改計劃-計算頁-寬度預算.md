# 修改計劃：計算頁寬度預算歸零重算

> **v2（2026/07/29 實測後修訂）**
> 已在真實 macOS Chrome（1710px 視窗、Retina）量測四頁。實測推翻了 v1 的三個假設，
> 修正處以「**實測**」標示。四頁量測結論見附錄 A，方案模擬驗證見附錄 B。

**日期**：2026/07/29
**範圍**：`css/calculator.css` 的 `.combined-interest-row` 相關規則
**目標**：讓「總利息／總繳款」「每年利息／每月利息」「稅金／稅後利率」「百萬利息」「一萬利息」五列，在 Android / iPhone / iPad / macOS Chrome 四種環境下都不裁切、不換行，並留下足夠緩衝
**原則**：不減少任何資訊、不縮字級、不改變欄位左右順序（維持業務的視覺肌肉記憶）

---

## 一、問題診斷

### 1-1 表面症狀

| 症狀 | 出現環境 | 使用者感受 |
|---|---|---|
| 「每年／每月」被擠成兩行 | macOS Chrome | 版面歪掉 |
| 右側出現明顯滾動條 | macOS Chrome | 佔空間、不美觀 |
| 總繳款 / 每月利息 / 稅後利率 數字右側被裁 | macOS Chrome 嚴重，手機輕微 | **數字看不到（最嚴重）** |

### 1-2 根因

**根因一：寬度預算零富餘**

可用寬度推導（viewport 由 `meta viewport content="width=400"` 鎖定為 400px）：

```
viewport                                    400px
− 滾動條（macOS Chrome 傳統捲軸 15px）        −15px  → 385
− body padding 0 3px（border-box）            −6px  → 379
− .output-group border 1px + padding 1px ×2   −4px  → 375
− .row padding 3px ×2                         −6px  → 369
────────────────────────────────────────────────────────
可用寬度：手機 384px ／ macOS Chrome 369px
```

各列實際需求（`input` 為 content-box，實寬 = width + padding 10 + border 2）：

**A 型列**（總利息／總繳款、每年利息／每月利息、稅金／稅後利率）

| 元素 | 計算 | 寬度 |
|---|---|---|
| `.label:first-child` | 75 + margin-right 4 | 79 |
| `input` | 85 + 10 + 2 + margin-right 10 | 107 |
| `.interest-separator` | 字寬 ~5 + margin 8×2 | 21 |
| `.label:not(:first-child)` | 65 + margin 4×2 | 73 |
| `input` | 85 + 10 + 2 + margin-right 10 | 107 |
| **合計** | | **387px** |

→ 手機溢出 3px、桌機溢出 18px，被 `.output-group` 的 `overflow: hidden` **裁掉**。這是數字看不到的原因。

**B 型列**（百萬利息、一萬利息）

| 元素 | 計算 | 寬度 |
|---|---|---|
| `.label:first-child` | 76 + margin-right 4 | 80 |
| `.sub-label`「每年」 | 32 + margin 8×2 | 48 |
| `input` | 64 + 10 + 2 + margin-right 10 | 86 |
| `.interest-separator` | ~5 + 16 | 21 |
| `.sub-label`「每月」 | 32 + 16 | 48 |
| `input` | 64 + 10 + 2 + margin-right 10 | 86 |
| **合計** | | **369px** |

→ 手機富餘 15px（正常）、桌機富餘 **0px**（剛好卡死）。

**根因二：`.sub-label` 是唯一可壓縮元素**

`.combined-interest-row` 是 flex 容器。`.label`、`input`、`.interest-separator` 都寫了 `flex-shrink: 0`，**只有 `.sub-label` 沒寫**（`css/calculator.css:1274`），也沒有 `white-space: nowrap`。

所以桌機少的那幾 px 全部由 `.sub-label` 吸收；中文 min-content 是單字寬，「每年」就被壓成「每／年」兩行。

**根因三：`input` 字型未指定，跨平台寬度浮動**

`font-family` 只寫在 `html, body`（`css/calculator.css:309`），而**表單控制項預設不繼承 font-family**。目前各平台 input 用的是各自的系統預設字型：

| 平台 | input 實際字型 | 16px 數字寬 |
|---|---|---|
| iPhone / iPad | -apple-system (SF) | ≈ 9.6px |
| Android | Roboto / One UI | ≈ 8.9px |
| macOS Chrome | 系統預設 | ≈ 8.9px |

以 8 位數金額 `12,345,678` 估算：Android ≈ 80px、iPhone ≈ 85px。A 型列 input 可用僅 85px → **iPhone 會裁切**。

另外 `check.css`、`invoice.css` 已有 8 處使用 `font-variant-numeric: tabular-nums`，**唯獨 `calculator.css` 完全沒有**，三頁不一致。

### 1-3 為什麼手機看不到問題

| 環境 | 滾動條型態 | 佔用寬度 |
|---|---|---|
| Android Chrome | overlay | 0px |
| iPhone Safari / Chrome（皆為 WebKit） | overlay | 0px |
| iPad Safari（含外接鍵盤／滑鼠） | overlay | 0px |
| macOS Chrome（接滑鼠或系統設定「一律顯示」） | 傳統，佔版面 | **15px** |

iOS / iPadOS 沒有「一律顯示捲動列」設定，所以行動裝置永遠是 overlay。手機因此有 15px 富餘，剛好蓋住問題。

## 三、修改步驟

四個步驟各自獨立、可單獨驗證、可單獨回滾。建議依序執行，每步驗證後再進下一步。

### 步驟 1：收斂桌機滾動條寬度

**動機**：把 macOS Chrome 的 15px 降到 6px，讓桌機與手機的可用寬度差距從 15px 縮到 6px，改版時所見即所得。

**位置**：`css/calculator.css`，加在 `html, body` 規則區塊之後

```css
/* ------------------------------------------------------------
 * 桌機捲軸收斂（2026/07）
 *
 * macOS / Windows Chrome 在接滑鼠時使用「傳統捲軸」，會實際佔用
 * 15px 版面寬度（實測確認）；行動裝置（Android / iOS / iPadOS）
 * 一律是 overlay 捲軸，佔用 0px。這 15px 差距正是桌機版面爆掉、
 * 手機正常的原因。
 *
 * 用 (hover: hover) and (pointer: fine) 把規則限定在「有精確指標
 * 裝置」的環境 —— 手機與平板永遠不符合此條件，因此本區塊對
 * Android / iPhone / iPad 是完全的 no-op，零風險。
 *
 * 【實測警告：絕對不要加 scrollbar-width: thin】
 * 兩者並存時 scrollbar-width 會蓋過 ::-webkit-scrollbar，Chrome 給的
 * 是 11px 而不是 6px（實測：加了得到 11px、拿掉才得到 6px）。
 * 只寫 ::-webkit-scrollbar 才能真的收到 6px。
 *
 * 不用 display: none 全隱藏，是為了保留「下方還有內容」的視覺提示。
 * ------------------------------------------------------------ */
@media (hover: hover) and (pointer: fine) {
    html::-webkit-scrollbar {
        width: 6px;
    }

    html::-webkit-scrollbar-track {
        background: transparent;
    }

    html::-webkit-scrollbar-thumb {
        background: rgba(255, 255, 255, 0.25);
        border-radius: 3px;
    }

    html::-webkit-scrollbar-thumb:hover {
        background: rgba(255, 255, 255, 0.4);
    }
}
```

**效果（實測）**：桌機捲軸 15 → 6px，列可用寬度 363 → **372px**。手機不變。

**決策點**：若你希望桌機**完全看不到**滾動條，把 `width: 6px` 改成 `display: none` 並移除 thumb/track 規則，桌機可用寬度會回到 384px、與手機完全一致。代價是失去可捲動提示。**建議先用 6px 版本，實測後再決定是否全隱藏。**

### 步驟 2：回收間距浪費

**動機**：全域 `input` 的 `margin-right: 10px` 與 `.interest-separator` 的 `margin: 0 8px` 疊加，造成中間 18px 的過寬間隔；行尾 input 的 10px 更是純浪費。

**位置**：`css/calculator.css:1258`（`.combined-interest-row input`）、`:1264`（`.interest-separator`）、`:1285`（sub-label override）

```css
/* 【改】.combined-interest-row input（原 :1258） */
.combined-interest-row input {
    width: 85px;
    font-size: 16px;
    flex-shrink: 0;
    margin-right: 4px;              /* 【新增】覆寫全域 input 的 10px */
}

/* 【新增】行尾 input 不需要右邊距 */
.combined-interest-row input:last-child {
    margin-right: 0;
}

/* 【改】.interest-separator（原 :1264） */
.interest-separator {
    color: var(--accent-color);
    margin: 0 4px;                  /* 【改】原 0 8px */
    font-weight: bold;
    font-size: 18px;
    flex-shrink: 0;
    position: relative;
    left: 0;
}

/* 【改】million / ten-thousand 的 sub-label（原 :1285） */
.million-interest-row .sub-label,
.ten-thousand-interest-row .sub-label {
    width: auto;
    margin: 0 4px;                  /* 【改】原 0 8px */
    font-size: 16px;
    flex-shrink: 0;                 /* 【新增】不再由它獨自吸收壓縮 */
    white-space: nowrap;            /* 【新增】雙保險，禁止中文斷行 */
}
```

**【實測後新增】同時收窄第一欄 label**

實測顯示：光做上面的間距回收，A 型列只降到 363px，而實際可用寬度也是 363px —— **緩衝仍是 0**，等於沒解決。必須同時收窄 label。

各 label 的文字實際需求：`總利息`/`總繳款`/`稅金` = 48px、`每年利息`/`每月利息`/`稅後利率`/`百萬利息`/`一萬利息` = 64px。目前給 75px / 76px，可安全收到 66px（保留 2px 餘裕）。

```css
/* 【改】.combined-interest-row .label:first-child（原 :1241） */
.combined-interest-row .label:first-child {
    width: 66px;                    /* 【改】原 75px；最長「每年利息」實需 64px */
    font-size: 16px;
    margin-right: 4px;
    text-align: right;
    flex-shrink: 0;
}

/* 【改】million / ten-thousand 的第一欄 label（原 :1292） */
.million-interest-row .label:first-child,
.ten-thousand-interest-row .label:first-child {
    width: 66px;                    /* 【改】原 76px；「百萬利息」實需 64px */
}
```

> **注意**：`flex-shrink: 0` + `nowrap` 必須**和其他步驟一起做**。單獨加這兩行會把「換行」變成「整列硬溢出、數字被裁」，是退步。

**效果（實測驗證，見附錄 B）**：

| 列型 | 原需求 | 改後需求 | 節省 |
|---|---|---|---|
| A 型 | 387px | **354px** | −33px |
| B 型 | 363px | **319px** | −44px |

### 步驟 3：input 改 border-box（等值換算，零視覺位移）

**動機**：目前 `width` 是內容寬，實寬要另外心算 +12px，是這次算錯預算的根源。改成 border-box 後 `width` 即實寬，日後調版不再需要心算。

**位置**：`css/calculator.css:1258`、`:1279`

```css
/* 【改】.combined-interest-row input */
.combined-interest-row input {
    box-sizing: border-box;         /* 【新增】 */
    width: 97px;                    /* 【改】= 舊 85 + padding 10 + border 2，實寬不變 */
    font-size: 16px;
    flex-shrink: 0;
    margin-right: 4px;
}

/* 【改】.million-interest-row / .ten-thousand-interest-row input（原 :1279） */
.million-interest-row input,
.ten-thousand-interest-row input {
    width: 76px;                    /* 【改】= 舊 64 + 10 + 2，實寬不變 */
    font-size: 16px;
}
```

**效果**：視覺上**完全零變化**，純粹是維護性整理。務必和步驟 2 分開 commit，方便對照驗證。

### 步驟 4：統一 input 字型與數字寬度

**動機**：消除跨平台數字寬度浮動，並與 `check.css` / `invoice.css` 既有的 `tabular-nums` 慣例對齊。

> **【實測修正】v1 高估了這項風險。**
> v1 估計 iPhone 的 SF 字型比 Android 的 Arial 寬約 8%，實測（Canvas measureText, 16px）為：
>
> | 內容 | Arial | SF (-apple-system) | PingFang TC |
> |---|---|---|---|
> | `863,672` | 57.8 | 60.8 | 61.0 |
> | `2,973,672` | 71.2 | 72.0 | 74.0 |
> | `12,345,678`（8 位數） | 80.1 | 81.1 | 81.2 |
> | `123,456,789`（9 位數） | 89.0 | 90.7 | 90.8 |
>
> 差距只有 1～3px（約 1.5%），**不是 8%**。8 位數在三種字型下都能塞進 85px 內容區。
> 所以本步驟**不是急件**，價值在於「讓寬度可預測、與另兩頁一致」，而非搶救 iPhone 裁切。
> 真正的天花板是 9 位數（億級），三種字型都會爆，屬於已知限制。

**位置**：`css/calculator.css`，加在 `.combined-interest-row input` 規則中

```css
.combined-interest-row input {
    box-sizing: border-box;
    width: 97px;
    font-size: 16px;
    flex-shrink: 0;
    margin-right: 4px;

    /* ------------------------------------------------------------
     * 【2026/07 新增】固定數字度量
     *
     * 表單控制項預設不繼承 font-family，因此 input 原本在各平台用的
     * 是系統預設字型：iOS 是 SF（數字約 9.6px）、Android 是 Roboto
     * （約 8.9px）。同一筆金額在 iPhone 上會比 Android 寬 8%，讓寬度
     * 預算無法計算。明確指定字型堆疊後三平台收斂到約 8.9px。
     *
     * tabular-nums 讓 0-9 等寬（"1" 不再比 "0" 窄），金額變動時欄位
     * 不會左右跳動 —— 與 check.css / invoice.css 既有作法一致。
     * ------------------------------------------------------------ */
    font-family: "Microsoft JhengHei", Arial, sans-serif;
    font-variant-numeric: tabular-nums;
}
```

**效果**：A 型列 input 內容區 = 97 − 10 − 2 = 85px。
`12,345,678`（8 位數）≈ 8 × 8.9 + 2 × 4.45 = **80px** → 三平台皆可完整顯示。

**已知上限**：9 位數（億級）金額 ≈ 89px 仍會裁切。重車貸款不預期出現，記錄備查。

**範圍限制**：本步驟只 scope 在 `.combined-interest-row input`，**不動**期數／稅前利率／本金／期繳等可編輯欄位。那些欄位較寬、風險低，待本批驗證穩定後再評估是否擴大。

→ 修正後**連警告動畫的最壞情況都撐得住**，這是現況做不到的。

## 附錄 A：四頁實測結果（2026/07/29, macOS Chrome, 視窗 1710px, DPR 2）

量測方式：於 `https://ryanlin02.github.io/my-website/` 逐頁切換，讀取各 iframe 內文件的

**calculator 損壞細節（實測）**

| 列 | 子元素需求 | 列可用 | 差額 | 末端元素被容器切掉 |

- `.sub-label` 實測高度 **45px**（正常單行應為 22.5px）→ 確認換行

  是整個 input 的右半部被 `.output-group` 的 `overflow: hidden` 切掉，切掉量 9px
- input 實測 `font-family` = **`Arial`**（body 是 `Microsoft JhengHei`）→ 確認 input 不繼承字型

**check 頁為什麼撐得住（實測）**

塞入 32 張票、8 位數金額、含「原 31 日」與「尾款票」標籤的最壞情況：

| 狀態 | 容器可用 | `col-date`（auto 欄） | table 溢出 |
|---|---|---|---|
| 無捲軸 | 362 | 140px | 0 |
| 有 15px 捲軸 | 347 | **125px** | **0** |

捲軸吃掉的 15px 完全由 `col-date: auto` 吸收，其餘固定欄位不受影響。
**這正面證明了「保留一個彈性欄」是有效的緩衝設計**，也是 calculator 缺少的東西。
