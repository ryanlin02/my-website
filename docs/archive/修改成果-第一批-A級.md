## 實際修好了什麼

### 1. 利率反推（A-1）

真實案例，本金 150 萬 / 36 期 / 期繳 6 萬：

| 欄位 | 修改前 | 修改後 |
|---|---|---|
| 稅前利率 | 20.0000% ❌ | **25.4534%** ✅ |
| 稅後利率 | 20.0000% ❌ | **23.8976%** ✅ |
| 佣後利率 | 20.0000% ❌ | **25.4534%** ✅ |

超過 100% 時顯示 `＞100%`，不會再給出一個看起來正常但是錯的數字。

### 2. 20% 警告（A-2）

上面那個案例現在會跳「警告：利率超過 20%，可能不符合一般貸款條件」。這個警告從寫進程式到今天，**一次都沒有跳過**，現在開始正常運作。

### 3. 金額上限（A-3）

| 欄位 | 修改前 | 修改後 |
|---|---|---|
| 本金 | 999,999,999 | 99,999,999 |
| 期繳 | **999,999** | **99,999,999** |
| 推廣費 | **999,999** | **99,999,999** |

實測解掉的案件：**本金 2,000 萬 / 12 期 → 期繳 1,739,769**，舊版打不進去，現在可以。

以及：本金 3,000 萬按「5%」快捷鍵 → 舊版被 999,999 截斷，現在正確得到 1,500,000。

### 4. 利率 >50% 的靜默夾擠

舊版輸入 60%，欄位顯示 60% 但期繳是用 50% 算的。現在欄位顯示的和實際計算用的永遠是同一個數字，超過 100% 直接擋下來。

### 5. 四條輸入路徑統一

舊版的上限**只擋數字鍵盤**。現在這四條路徑套用同一組限制：

- 數字鍵盤輸入
- 「+萬 / +千 / +100」微調鍵（舊版完全無保護）
- 「1%~5%」佣金比例快捷鍵（舊版完全無保護）
- 從歷史記錄「載入計算」（舊版完全無保護）

### 6. 佣金比例警告

超過 5% 時：欄位紅字常駐 + 跳一次「警告：佣金比例超過 5%，已超出內部規範標準」。

按「5%」快捷鍵得到剛好 5.00%，依「不可超過」的規範**不會**觸發警告，實測確認。

### 7. NaN 防呆

「稅後利率」欄位原本缺少防呆，超出範圍時會直接把 `NaN` 三個字印在畫面上。已補上，改顯示 `＞100%`。

## 順手做的一件事：所有門檻集中管理

`js/calc-engine.js` 最上方新增了一個設定區：

```js
var LIMITS = {
    MAX_AMOUNT: 99999999,     // 本金／期繳／推廣費 共用金額上限（元）
    MAX_PERIOD: 999,          // 期數上限（月）
    MAX_RATE: 100,            // 利率硬上限（%）
    RATE_WARN: 20,            // 利率警告門檻（%）
    RATIO_WARN: 5,            // 佣金比例警告門檻（%）
    MAX_FUNDING_COST: 20      // 資金成本上限（%）
};
```

**這對你的意義**：以後內部規範若從 5% 改成 4%，你只要把 `RATIO_WARN: 5` 的 `5` 改成 `4`，存檔、把 `sw.js` 的版本號加一號就好。不需要看懂任何程式碼。

這些數字原本散在 8 個不同位置，也正是「本金 10 億但期繳只能 99 萬」這種矛盾的來源。

## 驗證過程中的兩件事，據實說明

**第一件**：測試中一度出現「期繳存 47,004、載入變成 47,005」的紅字。追查後確認是**我的測試腳本設計錯誤** —— 我用了現實中不可能出現的組合（利率 8% 配期繳 47,004）。改用真實操作流程（自動算期繳 → 按「捨百」→ 存檔 → 載入）重測，期繳 47,000 與利率 7.9934% 都完整還原，正確。

**第二件**：另一個紅字是「期數 999 可輸入」失敗。原因是我的測試替身沒有模擬真實 `<input>` 會把數值轉成字串的行為。修正替身後通過。

兩件都是測試工具的問題，不是網站程式的問題。列出來是因為你看不懂程式碼，我不希望你只看到「全部通過」而不知道過程中有過反覆。

## 接下來要做什麼

**建議你先在電腦上實際點一遍**，特別是這幾項：

1. 隨便輸入一組正常案件（例如 36 期 / 8% / 150 萬），確認每個數字跟你印象中一樣
2. 打開歷史記錄，載入一筆舊資料，確認正常
3. 把期繳調到很高（例如 36 期 / 150 萬 / 期繳 6 萬），確認稅前利率顯示 25.4534% 並跳出警告
4. 佣金比例調到超過 5%，確認跳一次提示、連按不會一直跳

確認沒問題後再推上 GitHub。推上去之後，手機端要**關掉 App 再重新開啟一次**才會拿到新版（版本號已經加了，但 Service Worker 需要一次重啟來完成接管）。

**如果發現不對**：這批改動還沒 commit，可以完整還原到修改前的狀態，不會有任何殘留。
