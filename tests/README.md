# 測試說明

這些測試不會被部署到網站上，只在本機執行，用來確認改動沒有弄壞既有功能。

## 執行方式

### 不需安裝任何東西

```bash
node tests/大寫金額測試.js
node tests/invoice/verify.js
node tests/invoice/統編查詢測試.js
python3 scripts/build-taxid-index.py --self-test
```

### 需要先安裝 jsdom（模擬瀏覽器環境）

```bash
npm install jsdom          # 只需做一次
node tests/共用鍵盤測試.js
node tests/計算頁功能測試.js
node tests/支票頁功能測試.js
node tests/支票開票流程測試.js
node tests/支票進度與存檔測試.js
node tests/加油頁功能測試.js
node tests/版面守門測試.js
node tests/版面樣式測試.js
node tests/安裝教學測試.js
node tests/鍵盤行為對照測試.js
node tests/invoice/頁面載入測試.js
node tests/invoice/統編自動帶入測試.js
```

發票頁的測試自成一個資料夾 `tests/invoice/`，另有一份說明見 `tests/invoice/README.md`。

全部通過時結束碼為 0，有任何一項失敗會是 1，訊息裡會直接指出哪一項、預期值與實得值。

### 關於 XFAIL（目前只有 `加油頁功能測試.js` 用到）

加油頁是唯一還沒重構的頁面，有一批「已經知道、但還沒排到修」的問題。
這些項目標成 **XFAIL**（預期失敗）而不是 FAIL，所以不影響結束碼 ——
否則這支測試會永遠紅燈，失去當關卡的意義。

| 標記 | 意思 | 影響結束碼 |
|---|---|---|
| `PASS` | 正常通過 | — |
| `FAIL` | 真的壞了 | 是（1） |
| `XFAIL` | 已知問題、還沒修，符合預期 | 否 |
| `XPASS` | 該問題已被修好 | 否，但會提示你把 `xt` 改成 `t` |

每個 XFAIL 都標了它屬於 `修改計劃-加油頁.md` 的哪個階段。
**修完一個階段後，對應的 XFAIL 應該全部變成 XPASS —— 那就是該階段的驗收依據。**
看到 XPASS 就把那幾行的 `xt` 改成 `t`，它就升級成正式的守門測試。

## 各測試涵蓋範圍

| 檔案 | 需要 jsdom | 涵蓋內容 |
|---|---|---|

| `共用鍵盤測試.js` | 是 | 計算頁與支票頁兩頁都跑一遍：所有 `onclick` 函式是否存在、共用函式是否可用、鍵盤四則運算、Toast 與彈窗 |
| `計算頁功能測試.js` | 是 | 核心試算、利率反推、佣金連動、快捷調整鍵、輸入上下限、歷史記錄、清空、自動備份還原 |
| `支票頁功能測試.js` | 是 | A 級七項修正的迴歸驗證、尾款金額計算、開票日期列表、歷史記錄存讀 |
| `支票開票流程測試.js` | 是 | 實際開票流程：逐張打勾與進度、金額欄、尾款票區隔、日期調整標記、歷史記錄套用資料、打勾寫回工作紀錄、以尾款續開換票、螢幕不休眠 |
| `支票進度與存檔測試.js` | 是 | 改張數時保留有效打勾、漏開偵測與前往、只打勾 vs 改計算的分野、保存時覆蓋或另存、未儲存進度攔阻、自動暫存與 24 小時效期 |
| `加油頁功能測試.js` | 是 | 油價自動載入與離線 fallback、油錢/油量雙向換算（含連續切換方向）、折扣計算與上下限、千分位、清除鍵、油價對照表、DOM 結構不變式、原始碼守門（重複函式、div 平衡、`lastModifiedField` 五個入口）、拆檔與 `sw.js` 登記守門、GA4 白名單（裝假 `trackEvent` 實測按鍵不產生事件）、時鐘 rAF 停止、欄位 readonly 防系統鍵盤 |

| `版面樣式測試.js` | 是 | CSS 層級的守門：sticky 祖先鏈上不能有捲動容器、金額群組外框、空值收起規則、表格固定欄寬、!important 只准一處。**注意：目前只涵蓋 `check.html`，加油頁的結構驗證在 `加油頁功能測試.js` 裡** |
| `鍵盤行為對照測試.js` | 是 | 把「改動前」的兩份鍵盤實作與「改動後」的共用模組放進三個獨立沙箱，用 4 萬組隨機操作序列比對狀態是否完全一致 |
| `invoice/統編查詢測試.js` | 否 | `js/taxid-lookup.js` 單元測試：查得到/查不到、分片 404、離線、索引未建置自動休眠、同分片不重複下載、5xx 與壞掉的 JSON |

## 什麼時候一定要跑

- **改到 `arabicToChineseNumber()`** → 一定要跑 `大寫金額測試.js`

  這個函式的錯誤不會有任何報錯，只會安靜地產生一個少一個「零」的大寫金額。
  舊版就是這樣把 `1,005,000` 轉成「壹佰萬伍仟」（正確應為「壹佰萬零伍仟」），
  支票大寫漏字，銀行有權以文義不清、可被增改為由退票。

- **改到 `js/common-keypad.js`** → 一定要跑 `共用鍵盤測試.js` 加另外兩頁的測試

  這個檔案是計算頁與支票頁共用的，改壞了會兩頁一起壞。

- **在 `common-modals.js` 增減鍵盤按鍵** → 一定要跑 `共用鍵盤測試.js`

  它會檢查每一顆按鈕的 `onclick` 是否都指向真的存在的函式。
  過去就發生過鍵盤 HTML 呼叫 `calculatorDecimal()`、但支票頁沒有定義的情況，
  按下去只會在 console 丟 ReferenceError，畫面上完全沒有反應，很難察覺。

- **改到開票清單或打勾邏輯** → 一定要跑 `支票開票流程測試.js`

  這支測試裡有一項是把「第一批月票 + 第二批月票 + 第二批尾款」加總，
  驗證換票串接之後金額不會憑空多出來或漏掉。
  金額串接錯誤不會有任何報錯，只會讓客戶少付或多付。

- **改到打勾、歷史連結或存檔流程** → 一定要跑 `支票進度與存檔測試.js`

  這裡面最關鍵的一項是「客戶臨時改張數」：業務已經開好並打勾 12 張，
  客戶改口只給 15 張。前 14 張的日期與金額其實完全沒變，
  打勾必須保留下來 —— 舊版會把 12 個勾全部清空，
  而且不會有任何錯誤訊息，業務得憑記憶重點一次。

- **改到 `js/common-keypad.js` 或發票頁的 `padKey()`** → 一定要跑 `invoice/統編自動帶入測試.js`

  鍵盤對金額做「前導零正規化」（打 `0` 再打 `4` 會變成 `4`），
  但統一編號是編號不是數值，`04595257`（台積電）開頭那個 0 有意義，被吃掉就整組作廢。
  這個錯誤不會有任何報錯，只會讓某些客戶的統編怎麼打都打不對。

- **改到 `scripts/build-taxid-index.py` 的分片規則** → `PREFIX_LEN` 必須與
  `js/taxid-lookup.js` 裡的同名常數一起改，兩邊對不上會變成全部查不到。

- **改到 `pages/gas.html`、`css/gas.css` 或 `js/gas-engine.js`** → 一定要跑 `加油頁功能測試.js`

  加油頁的 `updateCalculations()` 曾經被重複定義兩次，後定義的覆蓋前定義。
  這造成「每月油量」欄位輸入後會被靜默蓋掉，以及折扣歸零時結果區不清空 ——
  兩者都不會報錯，只會讓業務拿著錯誤數字跟客戶談。
  這支測試把這些行為全部釘住了，並且有原始碼守門會檢查同名函式不准出現第二次。

- **寫「某段程式碼是否已移除」的守門測試** → 一定要先去掉註解

  本專案的註解習慣是把「為什麼移除某段程式碼」寫在原地，
  所以註解裡經常含有被移除程式碼的原文，例如
  `// 舊版是 setInterval(updateCurrentDate, 1000)。`
  直接搜尋原始碼會把註解也算進去，誤判成「還沒移除」。
  `加油頁功能測試.js` 裡的 `stripJsComments()` 與 HTML 註解過濾就是為此而寫，
  當初沒做這件事一次跳出 5 個假失敗。

- **在 `sw.js` 增減檔案** → 一定要跑 `加油頁功能測試.js`（第 16 群組）

  它會檢查 `css/gas.css` 與 `js/gas-engine.js` 有沒有留在預快取清單裡，
  也會反向檢查其他頁面的資源沒有被手滑刪掉。
  漏登記不會有任何錯誤訊息，只會在業務離線時整頁失效 ——
  而那通常是在客戶面前才發現。

- **在任何 CSS 檔新增 `var(--...)`** → 一定要跑 `加油頁功能測試.js`（第 19 群組）

  CSS 遇到**未宣告**的變數時，整條宣告會失效，而且不會報任何錯。
  `gas.css` 從第一版就引用了 `--text-primary` 與 `--button-hover` 這兩個
  從未宣告的變數，導致 `.calc-button.number:hover` 的背景色實際上是
  `transparent` —— 業務按計算機數字鍵時會看到按鍵閃一下變透明，
  這個 bug 躺了很久沒人發現，因為畫面「看起來只是有點怪」。

  第 19 群組會依各頁實際載入的 CSS 組合（例如 check.html 同時吃
  `calculator.css` 與 `check.css`）檢查四個頁面，另外也會擋下
  「內文出現與主題變數同值的硬寫死色碼」——那會讓改主題色時漏掉幾處。

- **動到任何頂端間距、標題列高度、或想新增一個「固定在頂端」的元素** → 一定要跑 `版面守門測試.js`

  「內容與標題列的距離」這件事被改過幾十次，而且經常是改對一個頁面、
  弄壞另一個頁面。原因不是手誤，是結構：內容的垂直位置原本由
  **5 個檔案裡 9 個互相牽連的數字**決定，每一個都是手調出來的。

  根本原因有兩個，現在都用規則擋住了：

  1. **外殼標題列的高度寫死在三個地方**（`.header-container` 的 height、
     `.content-container` 的 top 與 height），其中一個還寫錯 15px。
     現在三處都從 `--shell-header-h` 推導，改高度只要改一行。

  2. **頁內用 `position: fixed` 當頂列。** fixed 脫離文件流、不佔空間，
     所以下面每個元素都得靠 `padding-top` 手動讓開，而讓開的量必須等於
     固定列的高度 —— 字級一改就要重算。**改用 `sticky` 就沒有這個問題**，
     它會佔據自己的空間，內容永遠不會被蓋住。

  **規則：頁內頂列一律用 `sticky` 且 `top: 0`，禁止 `fixed`；
  頂端間距一律用 `--content-gap`，不准再出現手調的數字。**

- **改到 `css/` 底下任何檔案** → 一定要跑 `版面樣式測試.js`

  其他測試驗證的是行為，CSS 版面問題不會有任何行為異常 ——
  函式照跑、值也對，只是畫面長得不對，全部測試都是綠的。

  實際發生過：`calculator.css` 對 html/body 設了 `overflow-x: hidden`，
  這會讓 `overflow-y` 自動算成 `auto`、body 變成捲動容器，
  於是固定進度列黏在 body 的捲動框裡（等於整份文件高度），完全沒有固定效果。
  改用 `overflow-x: clip` 才不會建立捲動容器。
